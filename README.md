# NOVA STUDIO 3 — чёрный / лайм + GitHub Updates

## Запуск
Программа — один файл `NovaStudio.py`. Отдельный run_with_telegram.sh не нужен.
Один раз установи Python-зависимости:
```
python3 -m pip install PyQt6 Appium-Python-Client==6.0.7 cryptography
python3 NovaStudio.py
```
Для работы с физическим iPhone нужны Mac, совместимые Xcode, Appium/XCUITest, WebDriverAgent и доверенный подключённый iPhone. Это приложение не устанавливает их автоматически. Адаптация берёт фактический размер экрана, а не жёстко заданные координаты одной модели. Физические iPhone X–17 Pro Max здесь не проверялись: совместимость зависит также от версии iOS, Instagram, Xcode и WDA.

Telegram запускается вместе с основной программой при настроенном токене и разрешённом Telegram ID. Настройки и секреты сохраняются локально в JSON; никому не отправляй эти JSON. Уже раскрытый токен отзови через BotFather и внеси новый в окно настройки Telegram. Он не включён в архив.
Данные: Mac `~/Library/Application Support/NovaStudio`; Windows `%APPDATA%/NovaStudio`; Linux `~/.local/share/NovaStudio`. Обновление заменяет только программный .py, не эти данные.

## Настройка GitHub: один раз
### 1. Репозиторий
Создай на GitHub **публичный** репозиторий, например `nova-studio`, с веткой `main`. Эта версия клиента работает с публичными репозиториями без GitHub-токена. Не загружай аккаунты, пароли, Telegram-токен или приватный ключ в репозиторий.
Добавь содержимое этого архива в корень репозитория, включая **скрытую** папку `.github/workflows/release.yml` и `.gitignore`. Сам ZIP загружать в репозиторий вместо файлов не нужно.
Если работаешь через Git (подставь свой логин):
```
git clone https://github.com/USERNAME/nova-studio.git
```
Скопируй файлы архива в полученную папку, затем:
```
cd nova-studio
git add NovaStudio.py VERSION.txt CHANGELOG.md README.md .gitignore .github/workflows/release.yml
git commit -m "NOVA Studio 3: first release"
git push origin main
```
При необходимости войди в GitHub через GitHub Desktop или обычную авторизацию Git. Пароль GitHub в программу не нужен.

### 2. Ключ подписи
Открой программу → **Обновления → Ключ подписи**. Сохрани приватный ключ **вне папки репозитория**. Сохрани резервную копию в безопасном месте: для будущих выпусков нужен тот же ключ.
На GitHub открой репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
Name: **NOVA_SIGNING_KEY**.
Secret: содержимое файла приватного ключа (одна Base64-строка). Это не публичный ключ и не Telegram-токен. Не вставляй ключ в код, README или чат.
Workflow использует этот secret только при подписании; в приложение попадает только публичный ключ.
Если первый push запустил Action до добавления secret, это нормально: он завершится ошибкой. После настройки запусти вручную следующий шаг.

### 3. Первый выпуск
GitHub → **Actions → Build signed NOVA release → Run workflow → main → Run workflow**.
При необходимости включи Actions; в Settings → Actions → General должны быть разрешены GitHub Actions и создание релизов workflow (Contents: write).
Дождись зелёного статуса. На вкладке **Releases** появится `v3.0.0` с `NovaStudio.py`, `manifest.json`, `NovaStudio.zip`.
Друг скачивает **NovaStudio.zip из Releases**, не Source code.zip и не исходный архив из чата. В релизном .py уже прописаны твой репозиторий и публичный ключ; вручную настраивать их другу не нужно.
Не помещай скачанный релиз поверх разработческого файла репозитория: редактируй исходный `NovaStudio.py` из этого архива.

## Как отправить следующее обновление
1. В приложении **Обновления → Исходники** экспортируй код в пустую рабочую папку вне репозитория.
2. Отредактируй нужные модули. Через **Собрать .py** собери их обратно в `NovaStudio.py` в репозитории. Другу по-прежнему нужен только этот один .py.
   Альтернатива из терминала:
```
python3 NovaStudio.py --export-sources ../nova-sources
# отредактируй ../nova-sources/main.py или другой модуль
python3 NovaStudio.py --build ../nova-sources --output NovaStudio.py
```
3. Поменяй `VERSION.txt` с `3.0.0` на `3.0.1` (три числа, без буквы v) и кратко опиши изменения в `CHANGELOG.md`.
4. Commit и push в `main`:
```
git add NovaStudio.py VERSION.txt CHANGELOG.md
git commit -m "Release 3.0.1"
git push origin main
```
5. Actions проверит код, подпишет файлы, создаст draft, загрузит все файлы и только после этого опубликует релиз. Уже существующий номер не перезаписывается: для нового выпуска увеличивай VERSION.txt.
6. У друга при открытой программе выполняется фоновая проверка (при старте, затем примерно каждые 6 часов); можно нажать **Проверить версию** сразу. Затем **Установить и перезапустить**.
Автоустановка выключена по умолчанию. Друг может включить её; установка ожидает простоя, не прерывает выполняемую или незавершённую задачу и требует отсутствия открытых диалогов/введённых несохранённых паролей. Новая программа перезапустится. Предыдущий .py сохраняется как `.previous.py`.
Изменение локального кода или обычный push без нового номера версии само по себе не устанавливает обновление другу. Нужно успешное создание Release.

## Проверки и ограничения
Перед установкой проверяются Ed25519-подпись, SHA-256, размер, номер версии и принадлежность GitHub-релизу. Старые версии и повреждённые файлы отвергаются. Приватные репозитории, beta/prerelease и ветки raw/main не используются. Приватный ключ не отправляется клиенту.
GitHub API может ограничить частоту запросов; попробуй позже, не отключай проверку подписи. Фоновая работа Telegram продолжается пока работает основное приложение и компьютер не спит. Это не отдельный системный сервис.
Проверка без реального телефона и без публикаций:
```
python3 NovaStudio.py --self-test
python3 NovaStudio.py --doctor
```
В архиве не настроен реальный репозиторий. Первый опубликованный Release получает адрес автоматически от GitHub Actions. Если сохранял пустые/старые настройки источника в разработческой копии, в поле GitHub укажи свой OWNER/REPO, добавь публичный ключ из `.pub` рядом с приватным ключом и сохрани источник; приватный ключ в это поле не вводи.
